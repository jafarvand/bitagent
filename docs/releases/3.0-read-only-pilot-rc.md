# 3.0.0-rc.4 read-only pilot release candidate

Release `3.0.0-rc.4` is a bilingual fail-closed control plane for deciding whether a
specific tenant's evidence package is eligible for human review. It is not a
production approval and cannot enable controlled actions.

## Mandatory gates

| Gate | Repository/runtime evidence | External evidence required |
|---|---|---|
| Production identity | OIDC signature, issuer, audience, MFA, role, tenant and enforced RBAC posture | Identity-owner configuration and access review |
| Current access review | Approved, zero-exception, non-expired append-only receipt | Reviewer evidence reference |
| Audit integrity | Evidence and XIMA output hash chains verify | Retention and operational review |
| Governed knowledge | At least one approved, effective, non-expired tenant document | Knowledge-owner and privacy/retention acceptance |
| Secure delivery | Webhook secret configured and at least one tenant subscription | Approved source and destination connector ownership |
| Exchange API | All 14 OpenAPI `0.8.0-pilot` routes pass | Authentication, schema, freshness-SLA and owner report |
| Domain sources | All 20 operations, market/risk, AML, security and support routes live | Exact path inventory and freshness-SLA approval |
| Shadow reliability | Precision, recall, noise, report SLA, latency, load, soak, failover, restore, monitoring, runbooks and training pass | Real outcomes and eight domain-owner acceptances |
| Steering | Read-only pilot approval by at least two named approvers | Signed steering record |

## Operation

Copy `integration-input/release-evidence/pilot.example.json` to the ignored
`pilot.local.json`, replace placeholders only with truthful evidence, and open
`/pilot-readiness`. The API is
`GET /api/v0/releases/candidate?tenant_id={tenant}`.

The manifest includes every gate, every blocker, the external package SHA-256,
and a deterministic evidence receipt. It always returns
`controlled_actions_enabled=false`.
